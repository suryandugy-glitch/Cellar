Cellar Guard / User manual

Protect CSV imports. On every PR.

Catch CSV export changes that would break a customer’s import, before you ship. The checker runs with Java 21 or newer; the website shows synthetic examples.

Set up the PR gateFull technical manual

01 / Install

Build the Java checker.

Use a JDK (not only a JRE). Run these commands from the repository root.

git clone https://github.com/suryandugy-glitch/Cellar-Studio.git
cd Cellar-Studio
java Build.java test
java Build.java package
java -jar dist/cellar.jar validate --config cellar.json

To open the local web workspace, use sh run.sh (Windows: run.bat). Do not upload private customer CSV files to the public demo site.

02 / Check

A contract is the import promise.

Define required columns and row rules in cellar.json, then point the checker at the CSV produced by the code you plan to ship.

java -jar dist/cellar.jar check \
  --config cellar.json \
  --csv examples/sales.csv \
  --format markdown --summary

Exit 0: declared rules passed. Exit 1: blocking incompatibility. Exit 2: the check could not run, so nothing was verified. The sample CSV is for demonstration only.

03 / Pull requests

Run the check before merge.

The repository includes .github/workflows/guard-pr.yml. GitHub Actions executes it on every pull request to main.

Step 1

Generate the export.

Replace the workflow’s example CSV path with a representative CSV generated from the proposed application code.

Step 2

Review contracts.

Commit consumer expectations under version control. A checker cannot infer hidden customer requirements.

Step 3

Require the check.

In repository branch protection, require the Cellar Guard / csv-compatibility check before merging.

The included workflow checks the tracked synthetic CSV until you wire it to your application’s export command. For the complete configuration, report formats, troubleshooting and security boundaries, see the technical manual.
