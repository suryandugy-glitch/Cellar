# Resources, effort and budget

All budget figures below are **illustrative internal planning allowances in INR**, not current vendor quotes. They exclude taxes and currency conversion. Validate prices and choose services only when required. Hardware figures are starting recommendations to benchmark, not measured minimums.

## Local development and pilot

| Resource | Starting allocation | Why |
|---|---|---|
| Computer | Existing Windows/macOS/Linux laptop; 4 GB RAM, 1 GB free disk suggested | JDK, editor, source and test fixtures; no GPU needed |
| Java | Full JDK 21+ | Build/test; bundled JAR can run on a compatible runtime |
| Editor | Existing VS Code with Java support, or another Java IDE | No paid IDE requirement |
| Version control | Git repository and review workflow | Contract/source ownership and rollback |
| CI | Runner with JDK 21 and actual exporter dependencies | Check the real fixture on PRs |
| Data | Small representative synthetic fixtures, schema/consumer inventory | Avoid bringing client records into development |
| Backup | Separate controlled copy of contracts and release artifacts | Recover from local disk loss |
| Human time | Founder 6–8 h/week; reviewer 1–2 h/week when possible | Discovery plus reliable delivery |

No runtime database, AI API key, GPU, Node.js, Python, paid CSV parsing library or cloud subscription is required for the shipped application. Its source build uses only the JDK. Developing a customer's exporter may require that exporter's own tooling.

## Hosted pilot — future capacity hypothesis

Do not provision this for the local beta. After paid demand for shared coordination, start by testing a small Java application instance (for example 2 vCPU/4 GB RAM), a managed PostgreSQL database, object storage for redacted reports and a TLS endpoint. This is a load-test starting point, not a capacity guarantee. Avoid storing raw CSVs unless necessary and agreed.

| Proposed monthly category | Planning envelope |
|---|---:|
| Application compute | ₹1,000–₹3,000 |
| Database and backups | ₹1,000–₹3,000 |
| Object storage, transfer and logs | ₹200–₹1,000 |
| Email, monitoring and operational tools | ₹0–₹1,000 |
| Subtotal | ₹2,200–₹8,000 |
| 25% contingency | ₹550–₹2,000 |
| Total planning envelope | **₹2,750–₹10,000/month** |

Provider region, traffic, backups, retention and support can move costs outside this envelope. Personnel, payment fees, legal/accounting, taxes and acquisition are additional. Set usage caps/alerts before a public launch. Recheck pricing from official vendors when selecting providers.

## Capacity and measurement plan

Measure 1k, 10k and 100k synthetic rows with realistic columns and rules; record wall time, peak heap, issue count and output size. Test a failing-value-heavy file and high-cardinality uniqueness. Repeat with 1 and 4 concurrent API requests. Start with a 512 MiB Java heap for small trials and increase only after profiling. An 8 MiB CSV can consume much more heap when parsed. Refuse unsupported workloads rather than silently truncating rows.

The shipped release has correctness tests, not a published throughput/SLA guarantee. Prefer CI execution for infrequent checks; scale based on measured runs/minute and workload size, not number of registered users alone.
